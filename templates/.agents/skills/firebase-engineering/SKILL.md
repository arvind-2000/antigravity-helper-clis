# Professional Firebase Engineering in Flutter

Follow this guide to build, secure, optimize, and maintain Firebase integrations in Flutter applications following enterprise best practices.

---

## 1. Project Inspection & Architecture
Before introducing or modifying Firebase code:
- Inspect `pubspec.yaml` to identify installed Firebase packages (`firebase_core`, `firebase_auth`, `cloud_firestore`, `firebase_storage`, `cloud_functions`, `firebase_messaging`, etc.).
- Inspect initialization files (e.g., `firebase_options.dart` generated by FlutterFire CLI and initialization calls in `main.dart`).
- Identify the existing architectural patterns for state management, dependency injection, and data access.
- Preserve existing project conventions, folder hierarchies, and naming standards.
- Never modify or overwrite `firebase_options.dart`, `google-services.json`, or `GoogleService-Info.plist` without understanding their exact origin and purpose.

---

## 2. Firebase Authentication
- **Provider Support:** Implement required auth providers (Email/Password, Phone/SMS OTP, Google Sign-In, Apple Sign-In, Anonymous) cleanly.
- **Session Lifecycle:** Handle user registration, login, logout, password resets, email verification, and token persistence.
- **Auth State Streams:** Bind auth state listeners (`authStateChanges()`, `userChanges()`) to application state controllers, not individual widgets.
- **Security & Lifecycle:**
  - Safely handle expired refresh tokens, re-authentication requirements for sensitive operations, and account deletion.
  - Keep all authentication business logic outside UI widgets.

---

## 3. Cloud Firestore
- **Data Modeling:** Design shallow, query-optimized document structures and subcollections.
- **Typed Converters:** Utilize `withConverter<T>` for all collection and document references to enforce strongly typed models and safe JSON mapping.
- **Data Operations:**
  - Implement clean CRUD operations using typed repositories.
  - Implement queries with filters (`where`), sorting (`orderBy`), and cursor-based pagination (`limit`, `startAfterDocument`).
  - Use atomic transactions (`runTransaction`) for concurrent read-and-write updates (e.g., balance updates, inventory counters).
  - Use batch writes (`WriteBatch`) for grouped multi-document mutations.
- **Persistence:** Configure offline persistence and cache policies (`Source.serverAndCache`, `Source.server`, `Source.cache`) intentionally based on real-time requirements.

---

## 4. Firebase Storage
- **Uploads & Downloads:** Handle image and document uploads with clear MIME types and descriptive filenames.
- **Progress Monitoring:** Listen to upload/download task snapshots (`UploadTask.snapshotEvents`) to report real-time progress indicators in the UI.
- **Validation:** Enforce client-side file size and MIME-type constraints before initiating uploads to prevent wasting bandwidth.
- **Lifecycle & Metadata:** Support upload cancellation and pause/resume. Store necessary metadata (content type, custom attributes) alongside files.
- **Access Control:** Generate secure download URLs and coordinate path permissions with Firebase Storage Security Rules.

---

## 5. Cloud Functions
- **Server-Side Trust:** Keep critical business logic, payments, authorization checks, and trusted data calculations inside Cloud Functions rather than Flutter client code.
- **Callable vs. HTTP:** Use `HttpsCallable` for authenticated, context-aware RPCs (`FirebaseFunctions.instance.httpsCallable(...)`), handling auth context automatically.
- **Validation & Idempotency:** Validate request arguments and return typed responses. Handle retries and network idempotency safely.
- **Zero Server Secrets:** Never bundle Firebase Admin SDK service account keys or backend secrets inside the Flutter application.

---

## 6. Firebase Cloud Messaging (FCM)
- **Permissions:** Request notification permissions (`requestPermission`) gracefully with clear user-facing context.
- **State Handling:**
  - Foreground: Handle `FirebaseMessaging.onMessage` using local notifications or in-app banners.
  - Background / Terminated: Configure `@pragma('vm:entry-point')` background handlers and `FirebaseMessaging.onBackgroundMessage`.
  - Notification Opened: Handle `onMessageOpenedApp` and `getInitialMessage` to route users cleanly to target screens.
- **Token Management:** Manage FCM device tokens, handle token refreshes via `onTokenRefresh`, and synchronize tokens with user records in Firestore.
- **Deduplication:** Track notification IDs to avoid duplicate handling or duplicate navigation events.

---

## 7. Firebase Security
- **Server-Side Enforcement:** Enforce authorization rules strictly in `firestore.rules` and `storage.rules`. Never rely on client-side checks as the sole gatekeeper.
- **Least Privilege:** Write granular rules based on user authentication status (`request.auth != null`) and document ownership (`request.auth.uid == resource.data.userId`).
- **Zero Open Rules:** Never deploy or use open permissive rules (`allow read, write: if true;`) in production.
- **App Check:** Recommend and integrate Firebase App Check (reCAPTCHA v3, Play Integrity, DeviceCheck) to protect backend resources from abuse.
- **Secret Protection:** Never commit service account credentials, API private keys, or admin keys into client code or repository commits.

---

## 8. Performance & Cost Optimization
- **Query Restraint:** Never fetch whole collections when filtered, paginated, or indexed queries can retrieve only needed records.
- **Listener Management:**
  - Avoid unnecessary real-time snapshot listeners (`snapshots()`) when a one-time fetch (`get()`) suffices.
  - Always cancel and dispose of `StreamSubscription` instances when controllers or screens are disposed.
- **Denormalization:** Carefully denormalize frequently read, read-heavy data (e.g., author display names on post cards) to eliminate expensive secondary queries.
- **Budget & Cost Awareness:** Be conscious of read, write, and bandwidth quotas to prevent unexpected cloud costs.

---

## 9. Testing & Debugging
- **Firebase Emulator Suite:** Use the local Firebase Emulator Suite (`FirebaseFirestore.instance.useFirestoreEmulator(host, port)`) for local development and integration testing without incurring billing costs or touching live databases.
- **Error Handling:** Explicitly catch and categorize `FirebaseException`:
  - `permission-denied`
  - `not-found`
  - `already-exists`
  - `unavailable` / network timeouts
- **Verification:** Run `dart format`, `flutter analyze`, and unit/widget tests before finalizing changes. Never fabricate test results.

---

## 10. Execution Rules
- **Analyze First:** Inspect before modifying. Do not rewrite existing Firebase service layers without explicit justification.
- **No Weakened Rules:** Never weaken or open security rules to make an operation pass. Fix the client payload, auth token, or rule structure legitimately.
- **No Unauthorized Production Changes:** Ask before modifying live production data, deploying rules, or deploying Cloud Functions.
- **No Invented Schemas:** Never invent collections, document IDs, or field names. Use documented schema specifications or ask the user for backend requirements.

---

## 11. Final Report Checklist
When delivering a Firebase engineering task, report:
1. **Implemented Capabilities:** Services integrated, auth providers enabled, or database operations implemented.
2. **Files Created & Modified:** Complete list of paths.
3. **Security Measures:** Rules updated, authorization validations applied, and App Check configuration.
4. **Console Configuration Needed:** Any manual setup required in the Firebase Console (enabling auth providers, setting up composite indexes, configuring storage buckets).
5. **Verification Outcomes:** Formatting, static analysis, and test execution results.
